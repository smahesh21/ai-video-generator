# drishvo.co.in — development status

Last updated: 27 October 2026
Current stage: Internal account mode with MongoDB-backed projects and a hosted render worker. The signed-in creator flow now generates Gemini storyboards and complete ElevenLabs-narrated videos on the dedicated Google Cloud test VM, with private Cloudflare R2 output.

This is the ongoing checkpoint for feature work. Update it when a feature starts, changes scope, or is completed. `PROTOTYPE_STATUS.md` remains the detailed record of the earlier command-line video pipeline validation.

## Status key

- **Complete (local):** implemented and checked in this checkout, within the limits stated below.
- **Complete (hosted test):** deployed to the dedicated development cloud environment and verified there; production hardening may remain.
- **In progress:** actively being built; do not treat as ready.
- **Planned:** agreed direction, not implemented.
- **Later:** intentionally outside the current development phase.

## Current limitations

- The studio's account mode queues fixture renders in MongoDB, and a separate worker now runs on the dedicated Google Cloud test VM. The credential-free mode still launches its older local child process. The separate generation-state screen is still a UI simulation; the real job is on the Video render screen. A worker crash triggers one fresh attempt with a new ID after lease expiry; it does not resume partial MP4 work, and a second loss needs creator action. Queued account jobs wait if the worker is offline, and the Video screen explains worker availability. Account snapshots, stages, terminal status, and completed R2 Ready records are saved in MongoDB. New account-owned MP4s and posters use the private development `drishvo-develop` R2 bucket under `drishvo/renders/`. A complete hosted render, direct private R2 media verification, and running cancellation passed; signed-in browser playback of that disposable hosted output was not retained because the verifier cleans its data. Completed/cancelled directory cleanup and aggregate external alert delivery are deployed on the healthy hosted image. Google Cloud email alerts cover VM Error-or-higher logs, stop/delete requests, stale worker heartbeats, old queues, and repeated render failures emitted by the one-minute application timer. Recovery is recorded as a Notice log without opening an incident. Production-scoped R2 resources and capacity tuning also remain before launch. Local video bytes stream from disk, while R2 responses are currently buffered in server memory.
- Account mode is configured locally with MongoDB and one approved internal user. Previous browser drafts remain in local-mode storage and are intentionally not imported into accounts. Switching modes changes which workspace appears. Explicit project deletion removes its approval history.
- Gemini storyboard generation and ElevenLabs narrated rendering are connected in the signed-in account flow and passed one complete hosted browser test. The generated visual directions map to semantic schematic graphics with scene-specific continuous motion and narration-linked reveal/highlight cues rather than custom AI-generated footage. Existing MP4 files are immutable and must be rendered again to receive renderer improvements. Every storyboard and final video still needs human review for facts, pronunciation, caption sync, and visual quality.
- Fixture MP4s have silent synthetic narration timing and topic-matched schematic animation. They are real files, but they do not yet deliver custom AI-generated footage, ElevenLabs voice quality, or voice-to-motion synchronization described in the product goal. Unknown concepts can still fall back to a generic diagram, and local illustrative storyboards may still contain generic educational copy.
- The ignored `apps/studio/.env.current-login` file holds the latest locally issued sign-in details; the prior bootstrap credential file was removed. Signed-in users can change their password under Account. Forgotten-password email recovery is not yet available.
- Publish review now implements final confirmation, immutable delivery intents, direct/scheduled queueing, reschedule/cancel, delivery history, and explicit reconciliation for uncertain Meta outcomes. The publisher keeps R2 private and exposes only a short-lived hashed media URL for Meta. The Meta app, tester, permissions, ignored local credential, HTTPS callback, and feature flag are configured. Live consent was approved, but Instagram placed `smaheshsrisailam` under appeal review after human verification; the OAuth round trip and first live post cannot complete until Meta restores the account. The publisher is not started on the hosted VM because it still needs the Meta settings and a public HTTPS Studio origin.
